Setup (once)

  1. Put a fresh, full battery in. RPM depends on voltage — tune near match voltage or the numbers won't hold up.
  2. Deploy current code from Android Studio (Run).
  3. On the Driver Station, select the "Shooter Tuner" OpMode (don't start it yet).
  4. Connect a laptop to the robot's WiFi, open FTC Dashboard → 192.168.43.1:8080/dash.
  5. Set hoodPosition = 0.7, targetRPM = first row's value, feedPower = 0.
  6. (Optional) Add Target RPM and Actual RPM to the Dashboard graph so you can see the flywheel settle.

For each row, top to bottom

  1. Tape-measure the robot to the distance (goal → turret pivot). Place it there, turret aimed at the goal.
  2. Init + Start the OpMode. Flywheel spins up.
  3. Wait for Actual RPM to settle around target (bang-bang oscillates slightly — that's normal; wait until it hovers, not still climbing).
  4. Fire one ball — flick feedPower to fire then back to 0 (or feed with intake). Watch where it lands.
  5. Adjust targetRPM: lands short → +25–50; overshoots → −25–50.
  6. Re-fire, letting RPM recover to target between shots.
  7. When 3 shots in a row score, write that RPM in the table. Stop the OpMode.
  8. Move to the next distance, repeat.

Enter into code

  1. Replace the HOOD_0_70 table in ShooterAimingModel.java with your 18 pairs (ascending), and set the profile max to cover your top distance:
    new Profile("HOOD_0_70", 0.7, 70.0, 155.0, new double[][] {

    });
  2. Deploy, then verify: drive to a few random far spots and confirm it scores (the model interpolates between points).
  3. Commit ("far shot table retuned, 18 pts").

Keep it honest

  1. Same ball condition and battery state throughout — a tired battery mid-session skews the far numbers worst.
  2. Quick check once: at a parked spot, the Standby Dist (in) telemetry should match your tape within an inch or two (match aims off odometry; you measure with tape).
